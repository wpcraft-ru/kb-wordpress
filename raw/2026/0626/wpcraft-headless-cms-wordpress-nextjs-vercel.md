## Что такое Headless WordPress?

В традиционной архитектуре WordPress отвечает как за управление контентом (бэкенд), так и за его отображение пользователю (фронтенд) через систему тем и плагинов. Headless-подход («обезглавленный») разделяет эти две функции. WordPress становится исключительно системой управления контентом, которая предоставляет данные через API. Фронтенд же создается как отдельное независимое приложение. В нашем случае для создания этого приложения будет использоваться Next.js — фреймворк на базе React.

Взаимодействие между WordPress и Next.js происходит через GraphQL API, который можно легко организовать с помощью плагина WPGraphQL. Это позволяет разработчикам получать именно те данные, которые им нужны, и создавать высокооптимизированные, быстрые и безопасные пользовательские интерфейсы.

## Преимущества

- **Высокая производительность:** статические страницы (SSG), ISR для динамического контента
- **Повышенная безопасность:** разделение бэкенда и фронтенда сужает поверхность для атак
- **Масштабируемость:** CDN Vercel, глобальная сеть доставки
- **Developer Experience:** React, Next.js, Git, современные инструменты JS
- **Гибкость:** WordPress как источник данных для веба, мобильных приложений, IoT

## Пошаговое руководство

### Шаг 1: Настройка WordPress
- Установить WordPress
- Установить WPGraphQL (основной плагин)
- WPGatsby (опционально — отслеживание изменений контента)
- Проверить API через GraphiQL IDE

### Шаг 2: Создание проекта Next.js
```bash
npx create-next-app --example cms-wordpress my-wordpress-app
cd my-wordpress-app
```
.env.local: `WORDPRESS_API_URL=https://ваш-сайт.com/graphql`

### Шаг 3: Получение данных через getStaticProps
```js
export async function getStaticProps() {
  const allPosts = await getPostsForHome();
  return {
    props: { allPosts },
    revalidate: 10, // ISR
  };
}
```

### Шаг 4: Развертывание на Vercel
- GitHub/GitLab/Bitbucket
- Импорт в Vercel → автоматическое определение Next.js
- Environment Variables: WORDPRESS_API_URL
- Deploy → автоматическое обновление при пуше в main

## Edge Cache
- Статические страницы реплицируются на граничные серверы
- Минимальная задержка (контент с ближайшего сервера)
- Автоматическая масштабируемость
- ISR обновляет без редеплоя (<500 мс)

## Продвинутые возможности
- **ISR:** revalidate в getStaticProps
- **Preview Mode:** специальный API-маршрут для черновиков
- **CPT + ACF:** WPGraphQL for Advanced Custom Fields
