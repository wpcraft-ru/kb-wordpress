## Когда выбирать этот тип

Этот тип выбирают, когда проект автоматизирует бизнес-процессы, а не только публикует контент. Приоритет - правильная модель данных, роли, статусы и интеграции, а не количество страниц.

## Ключевые особенности

- Сложная предметная модель: сущности, связи, состояния и правила.
- Ролевая модель доступа для сотрудников, клиентов и партнёров.
- Процессная логика: согласования, уведомления, SLA, audit trail.
- Интеграции с внешними API, 1С, телефонией, платёжными сервисами.

## Оптимальный стек

- **Laravel + FilamentPHP** - основной выбор для систем с глубокой бизнес-логикой.
- **Next.js + Laravel API** - когда нужен насыщенный SPA-интерфейс.
- **JAMStack + Serverless** - только для лёгких утилит без тяжёлого бэкенда.

## Бриф-шаблон

1. Проблема: какой ручной процесс автоматизируем?
2. Пользователи и роли: кто работает в системе и с какими правами?
3. Сущности: заявки, клиенты, заказы, документы, платежи, задачи.
4. Главный сценарий: что происходит от входа до результата?
5. Бизнес-правила: расчёты, проверки, исключения, SLA.
6. Админка и отчёты: какие панели, экспорты и аудит нужны?
7. Интеграции: какие внешние системы обязательны на первом этапе?
8. UX: достаточно стандартного UI или нужен кастомный фронтенд?
